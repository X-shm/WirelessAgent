# 无线工具箱接口与验证契约

> 更新日期：2026-09-17。当前适用于 Wireless Toolbox 的 `129` 个注册工具和 `129` 份 schema。工具目录、产品归属、覆盖范围和验证状态以项目根目录的 `tool_registry.json` 为唯一事实来源；`README.md`、`tools/SKILL.md` 和 `VALIDATION.md` 均由该注册表生成。Bluetooth 的逐项完成度以 `bluetooth_capabilities.json` 为准。

## 1. 核心原则

一个工具不是“有一段可运行代码”就完成，而是以下四件事同时成立：

```text
注册范围（tool_registry.json）
    ↕
实现与 CLI（tools/<name>.py） ↔ 输入输出契约（tools/<name>.schema.json）
    ↕
验证策略（scripts/validate_<name>.py，MATLAB 黄金样本或独立性质测试）
```

- 工具名、Python 文件名和 schema 的 `name` 必须逐字一致；
- 每项注册工具必须有一份 schema 和一个可执行的验证策略；
- `validated` 仅说明 `coverage` 所述切片具有 MATLAB 对照或等价验证，`independent_validated` 仅说明独立验证通过；二者都不能超出 `coverage` 文字范围；
- schema、注册表和 CLI 发生不一致时，CI 必须失败；
- 不要把完整标准能力、设备控制能力或外部 Agent 项目的能力暗示为本仓库已有能力。
- Bluetooth 的 26 个 CLI 虽映射 52 个不同的 MATLAB 顶层名称，但名称映射或构造器可用均不等价于完整 MATLAB 对象生命周期、协议仿真或数值行为等价。

## 2. 命名与文件布局

### 2.1 命名

| 领域 | 前缀 | 示例 |
|---|---|---|
| 5G NR | `nr_` | `nr_pdsch`、`nr_dci` |
| LTE | `lte_` | `lte_ofdm`、`lte_srs` |
| WLAN | `wlan_` | `wlan_bcc`、`wlan_ldpc` |
| Bluetooth / BLE | `bluetooth_`、`ble_` | `bluetooth_test_waveform`、`ble_l2cap` |
| 通用通信 | 无强制前缀 | `qam_modulation`、`ofdm_equalizer` |
| 组合工作流 | 业务语义名 | `radio_link_diagnosis`、`closed_loop_validator` |

名称使用小写 `snake_case`。缩写沿用标准写法，例如 `ldpc`、`crc`、`ofdm`、`qam`、`prbs`，不为了英语完整性改变既有名称。

### 2.2 文件责任

```text
tool_registry.json                    # 范围、来源、状态、schema 路径的唯一事实来源
bluetooth_capabilities.json           # 52 个 Bluetooth 名称的能力切片与剩余缺口
tools/<name>.py                       # 可导入算法和命令行入口
tools/<name>.schema.json              # 用户/Agent 可消费的契约
tools/bluetooth_session.py            # SQLite 持久化 Bluetooth 对象会话入口
scripts/validate_<name>.py            # 专项验证器
matlab_oracle/gen_samples_<name>.m    # 需要 MATLAB 对照时的可选生成器
matlab_oracle/samples/<name>.json     # 已检入的黄金样本（如适用）
```

内部共享模块可以以 `_` 开头，但不得登记为工具或暴露为 CLI。所有从项目内读取的 Python 文件路径必须用 `Path(__file__)` 推导；MATLAB 生成器必须用 `wt_sample_dir`/`wt_sample_path` 推导样本路径，不能依赖当前工作目录或开发机盘符。

## 3. 注册表契约

每个 `tools` 条目至少包含：

- `name`：工具的唯一名称；
- `product`：来源产品/领域；
- `source_functions`：对应标准函数或组合来源；
- `status`：当前登记项使用 `validated` 或 `independent_validated`；
- `coverage`：明确写出端口、层数、配置、Release、资源映射、是否支持解码等边界；
- `schema`：对应 schema 的相对路径。

新增能力时应优先收紧或细化 `coverage`，而不是以“符合某标准”笼统描述。若新增样本、验证器或标准解释，需更新相关条目并重新生成派生文档。

## 4. Schema 与 CLI 契约

每份 schema 至少包含：

```json
{
  "name": "nr_xxx",
  "script": "nr_xxx.py",
  "description": "功能和范围说明",
  "implementation": "算法或标准子集说明",
  "inputs": {
    "bits": {"type": "string", "required": true, "description": "逗号分隔的比特"}
  },
  "outputs": {"result": "稳定的 JSON 输出字段"},
  "example": {"cmd": "python tools/nr_xxx.py --bits 1,0,1", "result": "{...}"}
}
```

- `inputs` 的 key 必须与 CLI `--flag` 逐字一致；
- 每个输入必须写出 `required`，可选项应给出 `default`、`enum` 或明确描述；
- 有位置子命令时，在 `subcommands` 中单独描述该子命令的输入；
- 输出 key 必须是稳定英文 key；复数数组使用明确的实部/虚部字段或统一的复数对象编码；
- 成功时 stdout 只输出 JSON。可预期的用户输入错误应返回机器可解析的 JSON 错误对象并以非零状态退出；
- 大型波形或中间阵列应提供摘要或文件输出选项，避免无界 JSON 响应。

大多数数值工具使用与 schema 同名的直接 flag，例如 `--snr_db` 或 `--bits`；不要假设存在统一的 JSON 输入 flag。`bluetooth_session` 是例外：它以互斥的 `--input '<JSON>'` 或 `--input_file <UTF-8 JSON 文件>` 接收操作、会话文件和对象字段。会话 API 用序号化的事件日志和筛选读取代替任意 Python/MATLAB 回调，避免把不可序列化的回调句柄写入跨进程状态。

`scripts/check_contracts.py` 当前检查名称、脚本、schema 输入、位置子命令、`--help` 与派生文档。新增工具还应补充示例执行、错误输入、默认值、枚举和输出形状的行为测试；不能仅依赖源码文本匹配。

## 5. 验证与 MATLAB 黄金样本

验证分为两条同等重要的路径：

1. **MATLAB 黄金样本。** 由对应 Toolbox 函数生成，Python 对同一输入进行逐比特或有阈值的数值比较；
2. **独立验证。** 使用标准公式、已知向量、往返、单调性、守恒关系或随机性质检查，不依赖 MATLAB 许可证。

MATLAB 生成器要求：

- 使用官方函数，而不是重新手写同一算法；
- 复数转置使用 `.'`，不能误用共轭转置 `'`；
- 固定随机种子，并将输入参数写入 JSON；
- 通过 `wt_sample_path('<file>.json')` 写入项目样本目录；
- R2026a 样本重生成后更新 `matlab_oracle/sample_manifest.json`；
- 若某项 Toolbox 未安装，必须明确记录为环境限制，不把未重生旧样本伪造为新版样本。

当前 R2026a Update 3 oracle 主机可用 5G、Bluetooth、Communications、LTE、WLAN 和 Wireless Network Toolbox。当前 manifest 记录 59 份 JSON：其中 58 份由该 MATLAB 基线重生，`polar_sequence.json` 是固定的 3GPP 数据。Wireless Network 的六个工具仍是无状态兼容子集，尚未定义 MATLAB 样本生成器。

## 6. 必跑检查

```bash
# Python 语法
python -m compileall -q tools scripts

# JSON、schema 基础结构和 MATLAB 样本哈希
python scripts/check_json.py
python scripts/generate_sample_manifest.py --check

# 注册表、schema、CLI 与生成文档
python scripts/generate_registry_docs.py --check
python scripts/check_contracts.py

# Bluetooth 的 52 个源名称是否可在当前 MATLAB 主机解析
matlab -batch "addpath('matlab_oracle'); verify_bluetooth_inventory"

# 全量专项验证与关键端到端回归
python scripts/validate_all.py
python scripts/test_nr_pdsch_e2e.py --perfect-only
```

在具备全部当前 Toolbox 的 R2026a 主机上，可重生全部现有 MATLAB 样本：

```matlab
addpath('matlab_oracle');
run_all_samples
```

只有 5G Toolbox 的 oracle 主机可使用 `run_5g_samples`。完成后执行 `python scripts/generate_sample_manifest.py --write ...`，传入实际 MATLAB 版本、可用 Toolbox、本次重生文件和任何固定标准数据文件；再运行全部 Python 验证。开源 CI 只验证已检入样本的完整性，不假设有 MATLAB 许可证。

## 7. 变更清单

- [ ] `tool_registry.json` 已更新来源、状态和精确 `coverage`；
- [ ] 实现、schema、帮助、示例和错误输出相互一致；
- [ ] 已选择 MATLAB 黄金样本或独立性质验证，并新增/更新专项验证器；
- [ ] MATLAB 生成器无硬编码路径且固定随机性；
- [ ] 样本内容变更后 manifest 已更新；
- [ ] 若变更 Bluetooth 工具，`bluetooth_capabilities.json` 已同步能力状态和剩余缺口；
- [ ] 已执行本节全部必跑检查；
- [ ] 已运行 `python scripts/generate_registry_docs.py --write`；
- [ ] 若需要接入外部 Agent/SkillOpt，由该外部仓库自行登记调用定义；本仓库不依赖该外部改动才能保持正确。
